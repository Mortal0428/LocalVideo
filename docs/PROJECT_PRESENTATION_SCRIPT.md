# CinemaAgent 工业级多媒体短剧视听与多智能体协同研创中台

## 答辩与技术演示完整逐字稿

### 一、总体介绍
各位评审老师、评委专家好！我汇报的项目是《CinemaAgent - 工业级多媒体短剧视听与多智能体协同研创中台》。

CinemaAgent 是一套专为竖屏微短剧、短视频创作者、影视制作机构及平台运营方量身打造的工业级视听与 AI 多智能体协同生产平台。系统向下攻克了海量短剧媒体资源的低成本高并发存储与秒级点播传输瓶颈，向上构建了由 10 大垂直领域专家组成的自主协同智能体蜂群，深度融合基于 LangGraph 原语的 Plan & Execute 动态待办清单工作流、黑板协同决策架构、多模态时间轴 Advanced RAG 检索中台以及 RAGAS 五维量化评测体系。

我们彻底攻克了传统短剧制作中“剧本立项流程割裂、分镜与制作周期漫长、内容违规机审滞后、大模型单体答疑胡说八道出现幻觉、多智能体协同流于形式变成自导自演假冒专家”等一系列深水区工程难题。

### 二、分哪些模块
整个系统在工程架构上清晰划分为前台沉浸业务视窗与后台技术支撑底座两大骨干体系：

#### 1. 前台业务应用一共分为五大核心模块：
1. **暗黑影院 9:16 拟态移动播放中心**：具备短剧连载无缝平滑切集、HTTP 206 秒级断点续播、动态点赞粒子微动画、评论实时互动及四轨道弹幕避碰流；
2. **多智能体沉浸协同圆桌会议室**：多专家环形在座可视化大屏，支持动态任务立项、实时脉冲声波展示、多专家自主接力推演以及 Plan & Execute 交互式任务待办看板；
3. **创作者工坊与智能分镜台**：涵盖剧本大纲结构化扩写、前 3 秒黄金吸睛钩子提取、九宫格分镜机位渲染与自动化导出交付工件；
4. **内容安全与人机合规风控中台**：集成 DFA 算法毫秒级违禁词过滤、智能拦截日志审计、涉政涉暴争议内容人工复核二次裁决看板；
5. **企业级全流程 BI 运营大屏**：实时监测短剧总播放量、用户停留时长漏斗、投流 ROI 预测、智能体调用拓扑与服务调用耗时监控。

#### 2. 后台技术支撑与管理系统一共分为六大核心底座：
1. **LangGraph 多智能体编排与状态图总调度引擎**：驱动多角色状态机转移、条件边动态规划与异常熔断自愈；
2. **多智能体黑板共享内存中枢（Blackboard Memory Hub）**：负责跨智能体结构化数据暂存、增量会话日志、冲突裁决与决策树收敛；
3. **中国联通沃盘对象存储桥接网关（OpenList 驱动）**：挂载海量云端多媒体资产，提供原生的 HTTP Range 分片代理与大文件转码流水线；
4. **模块化多模态 Advanced RAG 混合检索与评测底座**：融合 Neo4j 图数据库、ChromaDB 向量库、结巴分词倒排 BM25 检索，配合 Cross-Encoder 重排与 Self-RAG 反思过滤；
5. **双网关大模型服务调度矩阵**：支持云端高性能大模型（MiniMax / DeepSeek）与本地私有化 Ollama（Qwen2.5）无缝切换与离线容灾；
6. **企业级权限与安全底座**：基于 RBAC 的严格用户角色权限划分、密码加盐哈希及全链路操作行为审计体系。

#### 功能 A：多智能体蜂群协同与 Plan & Execute 动态待办编排

##### 1. 业务痛点与技术背景
在以往的多智能体演示系统中，业界普遍存在严重的“伪协同”硬编码弊病：要么不管用户问什么，系统都机械执行固定的 3 到 4 步骨架；要么总控大脑自导自演，一个人在后台把其他专家的答案全替他们编造完，下级智能体根本没有真正的领域思考，甚至因为 Prompt 污染导致垂直专家跑去查询无关的 MySQL 数据库，出现严重“牛头不对马嘴”的离题笑话。

##### 2. 核心架构设计与数据流向
为此，我们设计了真正的 Plan & Execute 动态待办流水线架构：
- **规划阶段（Plan Phase）**：
  当制片人在前端圆桌下达复合指令（例如：“做一个 todolist 列出主要事情，然后 5 个智能体发言圆桌总结”），请求进入后端路由，由总控大脑 `MasterOrchestratorPod.run_step()` 拦截，转交主控规划器 `dynamic_llm_planner()` 处理。
  规划器首先进行**研讨标的锁定（Mission Subject Anchor）**，提取出核心剧情研讨标的《高冷千金的贴身高手》工业化全链条研发，随后动态解析出不少于 5 个具有垂直专精分工的步骤清单（覆盖编剧、分镜、制片、合规、管家等）。
  大模型在此阶段严格禁止替专家答题，仅输出清晰的 Markdown 待办清单（`- [ ] Step N`）以及包含 `step_id`、`assigned_agent`、`role_badge`、`instruction` 的结构化 `task_pipeline` 数组。
- **执行阶段（Execute Phase）**：
  前端收到 `task_pipeline` 后，动态实例化 `currentTodoList` 响应式数据。
  调度引擎逐项执行待办任务，执行前将清单项状态置为 `in_progress`，并在前端实时点亮对应行的高亮状态；
  向对应垂直专家 Pod 派发专精 Prompt，Prompt 强制剔除制片人原本的操作性口语，严格封装为：
  `【圆桌协同研讨标的】：“${missionSubject}”` 与 `【本步骤专精任务】：${instruction}`。
  各领域专家在专属的垂直上下文约束下展开专业推理，推演完成后将结果写回黑板，前端将清单状态推进为 `completed` 并精准回显单步耗时（如 `18.2s`）。
- **终审收敛阶段（Consensus Phase）**：
  当所有待办清单执行完毕，系统收集黑板中所有专家的精要见解，注入 `run_summary()` 触发 9 号主控议长的终审决议生成，出具包含核心观点、综合推进策略与行动纲领的完整报告。

##### 3. 前端交互与工程呈现
前端在 `AgentRoundTableCanvas.vue` 中实现了优雅的现代化交互：
- 顶部动态卡片展示“X/Y 项已达成”进度胶囊徽标与平滑百分比动画轨道；
- 列表中每一个待办步骤根据状态实时切换灰色待定圆圈、蓝色微光脉冲 Spinner 动效、或者绿色完成勾选图标；
- 彻底修复了 SVG 图标由于弹性容器没有明确物理像素约束而撑满全屏变成粗黑线条的边界缺陷，整个界面呈现出克制、细腻的工业级质感。

#### 功能 B：多智能体黑板架构与圆桌会议协同共识

##### 1. 业务痛点与技术背景
当 10 位垂直领域专家并发工作时，如果采用传统的智能体点对点网状通信（P2P），通信复杂度将呈 $O(N^2)$ 指数级爆炸，且极易出现消息竞态、上下文信息衰减或相互死锁。

##### 2. 核心架构设计与数据流向
我们采用计算机体系结构中经典的黑板架构模式（Blackboard Architectural Pattern），构建了 `BlackboardMemoryHub` 共享状态中枢：
- **公共共享白板**：所有专家共享同一个基于 `session_id` 隔离的 `BlackboardTopic`。黑板内部维护三层结构：增量便签链（Notes）、结构化共识树（Consensus Tree）与冲突缓冲区（Conflict Pool）。
- **非对称读写协议**：专家 Pods 之间互不直接私聊，而是统一调用 `write_blackboard(topic_id, note)` 将推演方案挂牌到黑板上。写入过程由异步互斥锁 `asyncio.Lock()` 保护，防止多协程并发写入脏数据，每次成功写入均自增全局版本号 `version`；
- **智能冲突仲裁**：当不同专业角色的诉求产生客观冲突时（例如：5 号制片专家要求“单集预算压缩 30%”，而 8 号分镜导演要求“采用高规格雨夜飞车慢动作特写导致成本激增”），黑板检测模块将冲突项推入冲突池，触发 9 号常务主控议长的仲裁评估函数 `resolve_conflict()`，根据短剧当下阶段的 ROI 权重裁决最终方案，达成平衡共识后更新至共识树；
- **前端实时同步**：黑板底座通过 WebSocket 实时向前端广播便签事件，前端会话区与工件栏实时呈现各专家的思想火花，实现零延迟的多方协同。

#### 功能 C：智能意图识别与动态自适应路由分发中枢

##### 1. 业务痛点与技术背景
用户在平台的交互是多元化的，既有随意的闲聊打招呼，也有针对特定分镜画面的修改要求，还有跨多部门的大型立项会议指令。若所有请求都一股脑丢给全套多智能体，不仅浪费算力，还会导致简单任务响应迟缓。

##### 2. 核心架构设计与数据流向
我们在网关层 `AgentMeshRouter` 设计了动态意图分类与多路路由器：
- **语义意图分类器（IntentClassifier）**：
  提取用户输入的语义特征与槽位，将意图精确划分为：`SCRIPT_CREATION`（剧本编写）、`STORYBOARD_DIRECTING`（分镜机位）、`BI_QUERY`（数据分析）、`RISK_MODERATION`（合规风控）、`ROUNDTABLE_WORKFLOW`（圆桌工作流）及 `ECOSYSTEM_PLUGIN`（外部生态）等；
- **自适应路由分发**：
  - 若为单领域高纯度任务，路由网关毫秒级直连分发给对应的专精 Pod（例如直接将“给第二集安排一个反转钩子”路由给 1号 编剧），单步直接交付，避免沉重的工作流开销；
  - 若检测到跨领域、强依赖、或者包含“圆桌/todolist/全套”等复合关键词，路由器动态挂载 9号 主控议长，激活 LangGraph 状态图与黑板工作流；
- **双网关高可用调度与熔断自愈（LLMGateway）**：
  调度中枢对接云端模型与本地 Ollama Qwen2.5 实例。系统内置健康嗅探机制与 60 秒超时控制，一旦监测到网络波动或云端 API 频控限制，网关触发平滑降级，毫秒级无缝热切换至本地模型，确保生产环境绝对不挂起、不停服。

#### 功能 D：多模态视频时间轴 Advanced RAG 与 Self-RAG 反思质检

##### 1. 业务痛点与技术背景
传统文本 RAG 只能检索静态文档，完全无法理解视频这种富媒体时空载体。在短剧伴读场景下，观众提问“男主什么时候亮出真实身份？”，传统大模型如果单靠记忆，极易凭空捏造集数或胡乱编造情节；并且观众需要的是“精确到分秒”的定位与即刻跳转，普通问答体验极其割裂。

##### 2. 核心架构设计与数据流向
我们自主研发了多模态时间轴视频 RAG 引擎与 Self-RAG 反思防御体系：
- **离线知识切片准备（Video Multimodal Chunking）**：
  利用 FFmpeg 抽取视频音轨与关键帧，经由 OCR 文字识别与 Whisper 语音转录，生成包含精准起始与结束时间戳（`start_sec` ~ `end_sec`）、视觉场景描述、人物关系变化的结构化切片；
  分块采用重叠窗口算法，确保人物长对话不会在时间边界被生硬斩断；切片数据经本地向量模型计算，存入向量数据库，同步用结巴分词建立 BM25 倒排索引；
- **在线三路混合召回（Hybrid Search with RRF Fusion）**：
  用户提问时，系统并发调起三路召回通道：
  - 通道 1：向量密集语义检索（Dense Retrieval），捕捉语义抽象接近的剧情；
  - 通道 2：BM25 稀疏关键词检索（Sparse Retrieval），锁定人名、道具名与特定台词；
  - 通道 3：时间轴跨度检索，定位上下文相邻的情节转折；
  三路候选利用 RRF（倒数排名融合算法）综合归一化排队，再经过 Cross-Encoder 深度重排器（Reranker）打分，挑选出置信度最高的黄金切片；
- **Self-RAG 四标记抗幻觉自省过滤**：
  模型在生成答案前后执行严格的四重反思质检：
  1. `should_retrieve`：判断问题是否确实需要检索剧集知识库；
  2. `is_relevant`：判断检索到的视频时间轴切片是否与问题相关，若不相关则启动 CRAG 纠错；
  3. `is_supported`：质检核心防线！大模型生成的回答正文必须 100% 能够在检索到的切片文本中找到原文支撑，若存在凭空捏造的剧情，直接打回拦截并重写；
  4. `is_useful`：评估回答对用户是否有真实指导价值；
- **前端播放器联动与毫秒级时间戳跳转**：
  问答结果返回前端后，正文中所有涉及剧情关键点的段落均会自动转化为高亮的时间胶囊按钮（如 `[02:15 身份摊牌]`）。用户轻轻一点，左侧的 9:16 移动播放器立即触发 `videoElement.currentTime = 135`，实现毫秒级精准定点 Seek 连贯播放！

#### 功能 E：基于 RAGAS 的量化评测体系与自动化故障诊断决策树

##### 1. 业务痛点与技术背景
在生产级 AI 系统研发中，绝不能依靠肉眼“抽查几条凭感觉判断效果好坏”。调整了切片分块步长、修改了重排阈值，到底有没有提升系统表现？必须有真实客观的量化数据支撑。

##### 2. 核心架构设计与工程突破
我们构建了基于 RAGAS 理论的自动化量化评测流水线 `RagasEvaluator`：
- **黄金评测基准集（Golden Benchmark）**：
  精心构建了覆盖短剧核心主线剧情、人物背景细节、时间轴跨度推断等真实业务场景的测试集，包含真实问题、标准切片上下文与真实标准答案；
- **五维量化雷达打分**：
  评测围绕生成式检索的核心指标自动化运行：
  1. 真实忠实度（Faithfulness）：检测回答是否存在幻觉编造；
  2. 回答相关度（Answer Relevance）：检测回答是否切中题意；
  3. 上下文精度（Context Precision）：评估检索到的前排切片命中率；
  4. 上下文召回率（Context Recall）：评估关键剧情信息的覆盖全面性；
  5. 调和平均值（Harmonic Score）：综合健壮性评分；
- **工程并发优化突破**：
  原先逐道题多次调用大模型打分，单次评测耗时高达上百秒。我们通过多维打分聚合优化，结合多线程并发执行，将 8 套完整基准题的端到端评测耗时大幅缩减，前端可视化呈现直观的优化前后雷达对比图；
- **故障诊断决策树**：
  系统在评测结束后自动出具“工程处方”：当忠实度低时建议调低模型温度并开启 Self-RAG 严格过滤；当召回率低时建议减小切片分块步长并提升 BM25 融合权重，实现了“从指标监控到闭环调优”的科学迭代。

#### 功能 F：AI 脚本分镜自动化生成与多模态资产反哺闭环

##### 1. 业务赋能与价值落地
AI 智能体最终必须落脚到降低创作者门槛与实际降本增效上：
- 在创作者工坊中，编剧输入简短梗概，系统调度 1号 编剧与 8号 分镜专家，自动扩写出符合短剧竖屏拍摄规范的分镜头脚本，包括景别（特写/全景）、机位运动（推镜头/摇镜头）、台词与音效提示；
- 结合多模态大模型对视频高能切片自动打标，提取出的关键镜头与脚本元数据反哺存入知识库，使得数字资产随着生产不断自生长，形成“创作 - 剪辑 - 沉淀 - 检索”的飞轮闭环。

### 四、总结：在本次项目中收获了什么 / 得到了什么提升
在 CinemaAgent 这一企业级项目的全生命周期研发中，我获得了全方位的工程架构与系统思维蜕变：

1. **从“单体 Prompt 调优”到“工业级多智能体协同工程”的认知升维**：
   我深刻体会到，构建真正落地的 Agent 系统，绝非写几句提示词那么简单，必须具备扎实的状态机控制、黑板通信协议、数据隔离与防死锁设计，才能彻底告别假冒专家的脆弱玩具系统，掌控复杂状态图的确定性。
2. **严苛的生产级抗幻觉与量化调优能力**：
